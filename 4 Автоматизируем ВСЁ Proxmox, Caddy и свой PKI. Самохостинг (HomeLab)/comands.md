# Развертывание локального удостоверяющего центра (Step-CA) и интеграция с Reverse Proxy

Настоящая инструкция описывает процесс развертывания службы Step-CA в ОС Arch Linux, настройку окружения (Systemd, nftables) и настройку автоматического получения TLS-сертификатов через веб-сервер Caddy.

## Этап 1. Установка пакетов и подготовка системного окружения

Для повышения безопасности служба Step-CA должна функционировать от имени выделенного бесправного пользователя.

1. Установите необходимые пакеты:
   ```bash
   sudo pacman -S step-ca step-cli --noconfirm
   ```
2. Создайте системного пользователя и рабочую директорию:
   ```bash
   # Создание пользователя step без права входа в оболочку
   sudo useradd --system --user-group --shell /usr/bin/nologin --home-dir /etc/step-ca step
   
   # Создание рабочей директории
   sudo mkdir -p /etc/step-ca
   ```

## Этап 2. Инициализация инфраструктуры открытых ключей (PKI)

Генерация первичных ключей производится во временной директории текущего пользователя с последующим переносом.

1. Запустите процесс инициализации удостоверяющего центра:
   ```bash
   step-cli ca init
   ```
2. Укажите следующие параметры при запросе системы (замените значения в скобках на актуальные):
   * **Deployment Type:** `Standalone`
   * **Name:** `Local CA`
   * **DNS:** `<IP_СЕРВЕРА_CA>`
   * **Address:** `:9000` *(Обязательно наличие двоеточия перед портом)*
   * **Provisioner:** `<ВАШ_EMAIL>`
   * **Password:** `<ЗАДАННЫЙ_ПАРОЛЬ>`
3. Добавьте поддержку протокола ACME для автоматизированного взаимодействия с Caddy:
   ```bash
   step-cli ca provisioner add acme --type ACME
   ```

## Этап 3. Миграция конфигурации и настройка прав доступа

Перенос сгенерированных файлов из пользовательской директории в системную с корректировкой конфигурационных путей.

1. Скопируйте данные:
   ```bash
   sudo cp -r ~/.step/* /etc/step-ca/
   ```
2. Скорректируйте пути в конфигурационных файлах (замена пользовательской директории на системную):
   ```bash
   sudo sed -i "s|$HOME/.step|/etc/step-ca|g" /etc/step-ca/config/ca.json
   sudo sed -i "s|$HOME/.step|/etc/step-ca|g" /etc/step-ca/config/defaults.json
   ```
3. Создайте файл авторизации для автоматического старта службы (замените `<ЗАДАННЫЙ_ПАРОЛЬ>` на пароль из Этапа 2):
   ```bash
   sudo sh -c 'echo "<ЗАДАННЫЙ_ПАРОЛЬ>" > /etc/step-ca/password.txt'
   ```
4. Назначьте права доступа:
   ```bash
   sudo chown -R step:step /etc/step-ca
   sudo chmod 600 /etc/step-ca/password.txt
   ```

## Этап 4. Конфигурация системной службы Systemd

Создание файла переопределения (override) для управления параметрами запуска службы.

1. Создайте директорию для файла переопределения:
   ```bash
   sudo mkdir -p /etc/systemd/system/step-ca.service.d
   ```
2. Откройте файл для редактирования:
   ```bash
   sudo nano /etc/systemd/system/step-ca.service.d/override.conf
   ```
3. Внесите следующие параметры:
   ```ini
   [Service]
   User=step
   Group=step
   ExecStart=
   ExecStart=/usr/bin/step-ca /etc/step-ca/config/ca.json --password-file /etc/step-ca/password.txt
   WorkingDirectory=/etc/step-ca
   ```
4. Примените конфигурацию и запустите службу:
   ```bash
   sudo systemctl daemon-reload
   sudo systemctl enable --now step-ca
   ```
5. **Проверка:** Убедитесь, что служба запущена.
   ```bash
   sudo systemctl status step-ca
   ```
   *Ожидаемый статус: `active (running)`.*

## Этап 5. Настройка межсетевого экрана (nftables)

Разрешение входящего трафика на порт удостоверяющего центра.

1. Откройте конфигурационный файл nftables:
   ```bash
   sudo nano /etc/nftables.conf
   ```
2. В цепочке входящего трафика (`chain input`) добавьте правило разрешения порта 9000 для локальных интерфейсов:
   ```nft
   # Разрешение доступа к службе Step-CA
   tcp dport 9000 accept
   ```
3. Перезапустите firewall:
   ```bash
   sudo nft -f /etc/nftables.conf
   ```

## Этап 6. Настройка обратного прокси-сервера (Caddy)

Интеграция сторонних серверов Caddy с локальным удостоверяющим центром. Действия выполняются на целевом сервере.

1. Выведите содержимое корневого сертификата на сервере CA:
   ```bash
   cat /etc/step-ca/certs/root_ca.crt
   ```
2. Скопируйте выведенный текст (включая строки `BEGIN` и `END`).
3. На сервере Caddy создайте файл сертификата и вставьте скопированный текст:
   ```bash
   sudo nano /etc/caddy/root_ca.crt
   ```
4. Отредактируйте глобальную конфигурацию `/etc/caddy/Caddyfile`:
   ```caddy
   {
       # Глобальный ACME endpoint локального УЦ
       acme_ca https://<IP_СЕРВЕРА_CA>:9000/acme/acme/directory
       
       # Путь к доверенному корневому сертификату
       acme_ca_root /etc/caddy/root_ca.crt
   }
   
   # Пример конфигурации локального сервиса
   service.local {
       reverse_proxy localhost:8080
   }
   ```
5. Перезапустите службу Caddy:
   ```bash
   sudo systemctl restart caddy
   ```

## Этап 7. Интеграция сертификата в клиентские ОС

Для корректной работы браузеров без предупреждений о безопасности, файл `root_ca.crt` необходимо добавить в системные хранилища доверенных сертификатов на клиентских устройствах.

* **Windows:** Импорт через интерфейс в хранилище **Доверенные корневые центры сертификации**.
* **Android:** Настройки -> Безопасность -> Установка сертификата CA.
* **Linux:** Копирование файла в `/etc/ca-certificates/trust-source/anchors/` с последующим выполнением команды `update-ca-trust`.

# Руководство по эксплуатации локального удостоверяющего центра (Step-CA)

Документ описывает штатные процедуры обслуживания локального PKI: публикацию новых сервисов, дистрибуцию сертификатов на клиентские устройства и ручной выпуск SSL-сертификатов.

## Сценарий 1. Публикация нового сервиса (Автоматический режим через Caddy)

Процесс получения сертификата для новых внутренних доменных имен полностью автоматизирован на стороне веб-сервера.

1. **Маршрутизация (DNS):**
   Убедитесь, что целевое доменное имя (например, `dashboard.local`) ссылается на IP-адрес сервера Caddy в локальном DNS или файле `hosts`.
2. **Конфигурация Caddyfile:**
   Добавьте блок виртуального хоста в конфигурационный файл `/etc/caddy/Caddyfile`. Дополнительные параметры SSL не требуются.
   ```caddy
   dashboard.local {
       reverse_proxy localhost:3000
   }
   ```
3. **Применение конфигурации:**
   ```bash
   sudo systemctl reload caddy
   ```
   *Результат: Caddy автоматически запросит и установит сертификат через ACME-протокол.*

## Сценарий 2. Дистрибуция корневого сертификата по сети

Добавление доверия к локальному УЦ на новых клиентских устройствах без необходимости ручного копирования файлов.

1. Убедитесь, что клиентское устройство подключено к локальной сети.
2. Откройте веб-браузер и перейдите по ссылке (игнорируя предупреждение о безопасности самого соединения):
   `https://<IP_СЕРВЕРА_CA>:9000/roots.pem`
3. Загруженный файл `roots.pem` необходимо импортировать в системное хранилище **Доверенные корневые центры сертификации** клиентской операционной системы.

## Сценарий 3. Ручной выпуск TLS-сертификатов (Standalone)

Метод применяется для сервисов, не поддерживающих ACME-протокол или находящихся за пределами управления Caddy (например, СУБД, скрипты).

1. Убедитесь, что на целевой машине установлена утилита `step-cli`.
2. Получите корневой сертификат (см. Сценарий 2) и сохраните его локально под именем `root_ca.crt`.
3. Выполните команду генерации сертификата и закрытого ключа:
   ```bash
   step-cli ca certificate "db.service.local" service.crt service.key \
     --ca-url=https://<IP_СЕРВЕРА_CA>:9000 \
     --root=root_ca.crt
   ```
   *Система запросит выбор Provisioner-профиля и ввод административного пароля.*

## Сценарий 4. Мониторинг состояния и администрирование

**Проверка доступности службы (Health Check):**
Для проверки работоспособности сервиса с любого узла сети выполните:
```bash
curl -k https://<IP_СЕРВЕРА_CA>:9000/health
```
*Ожидаемый вывод: `{"status":"ok"}`.*

**Действия при изменении IP-адреса сервера CA:**
Изменение сетевых реквизитов сервера требует обновления конфигурации зависимых узлов:
1. Замена IP-адреса в директиве `acme_ca` файла `/etc/caddy/Caddyfile`.
2. Внесение изменений в файл `/etc/step-ca/config/ca.json` на самом сервере CA.
3. Перезапуск соответствующих служб (`step-ca` и `caddy`).
