# 1. Настройка монтирования сетевой папки (SMB) для непривилегированных LXC-контейнеров

Данная конфигурация использует метод двойного монтирования (bind mount) для обхода ограничений прав доступа (ошибка `Permission Denied`) при записи данных из непривилегированных контейнеров на внешний NAS-сервер.

**Исходные данные (пример):**
* IP-адрес NAS: `172.20.50.1`
* Имя сетевой папки: `ваша_шара`
* Целевая подпапка: `путь_к_данным_контейнера`

## Этап 1. Создание файла учетных данных

Для обеспечения безопасности логин и пароль от SMB-сервера выносятся в отдельный скрытый файл с ограниченными правами доступа.

1. Откройте терминал хоста Proxmox и создайте файл:
   ```bash
   nano /root/.smbcredentials
   ```
2. Внесите учетные данные (без пробелов до и после знака равенства):
   ```ini
   username=ваш_логин
   password=ваш_пароль
   ```
3. Ограничьте права доступа к файлу (чтение и запись только для суперпользователя `root`):
   ```bash
   chmod 600 /root/.smbcredentials
   ```

## Этап 2. Подготовка директорий на хосте Proxmox

Необходимо создать две директории: скрытую (техническую) для монтирования корня сетевого диска и рабочую (чистовую) для передачи в контейнер.

1. Выполните команды:
   ```bash
   mkdir -p /mnt/.nas_root_hidden
   mkdir -p /mnt/working_dir
   ```

## Этап 3. Конфигурация /etc/fstab

Настраиваем автоматическое двойное монтирование при старте системы. Принудительная подмена идентификатора пользователя (`forceuid`) гарантирует, что контейнер сможет записывать данные.

1. Откройте конфигурационный файл файловых систем:
   ```bash
   nano /etc/fstab
   ```
2. Добавьте следующие параметры в конец файла:
   ```bash
   # 1. Техническое монтирование корня NAS с подменой UID
   //172.20.50.1/ваша_шара /mnt/.nas_root_hidden cifs credentials=/root/.smbcredentials,uid=100000,gid=100000,forceuid,forcegid,dir_mode=0777,file_mode=0777,iocharset=utf8,noperm,nofail 0 0

   # 2. Проброс (Bind) целевой подпапки в рабочую директорию
   /mnt/.nas_root_hidden/путь_к_данным_контейнера /mnt/working_dir none bind 0 0
   ```
3. Примените изменения в системном демоне и смонтируйте диски:
   ```bash
   systemctl daemon-reload
   mount -a
   ```

**Проверка:** Выполните команду `ls -ln /mnt/working_dir`. Владельцем директории и файлов должен числиться пользователь `100000` (идентификатор `root` внутри непривилегированного LXC).

## Этап 4. Проброс директорий в контейнер

1. Используйте утилиту `pct` для привязки созданной папки к конфигурации контейнера (замените `100` на ID вашего контейнера):
   ```bash
   pct set 100 -mp0 /mnt/working_dir,mp=/путь/внутри/контейнера
   ```
2. Перезагрузите контейнер:
   ```bash
   pct reboot 100
   ```

**Проверка:** Войдите в контейнер (`pct enter 100`), создайте тестовый файл `touch /путь/внутри/контейнера/test.txt` и убедитесь в отсутствии ошибок доступа.

# 2. Настройка прямого сетевого соединения (Point-to-Point)

Инструкция описывает настройку изолированной подсети с маской `/31` для обеспечения прямой маршрутизации трафика между гипервизором Proxmox VE и сервером хранения данных (NAS) без участия центрального маршрутизатора.

## Этап 1. Настройка сетевого интерфейса в Proxmox

1. Откройте конфигурационный файл сетевых интерфейсов:
   ```bash
   nano /etc/network/interfaces
   ```
2. Отредактируйте блок настроек для выделенного физического порта (например, `nic1`), назначив статический IP-адрес:
   ```text
   auto nic1
   iface nic1 inet static
           address 172.21.6.254/31
   ```
3. Примените конфигурацию сети:
   ```bash
   ifreload -a
   ```
4. Убедитесь, что IP-адрес присвоен интерфейсу:
   ```bash
   ip a show nic1
   ```

## Этап 2. Настройка сетевого интерфейса в Arch Linux (NAS)

1. Откройте конфигурационный файл целевого интерфейса (например, `enp8s0`) в `systemd-networkd`:
   ```bash
   sudo nano /etc/systemd/network/10-enp8s0.network
   ```
2. Укажите параметры сопряженного IP-адреса:
   ```ini
   [Match]
   Name=enp8s0

   [Network]
   Address=172.21.6.255/31
   ```
3. Перезапустите сетевую службу:
   ```bash
   sudo systemctl restart systemd-networkd
   ```

**Проверка:** Выполните команду `ping 172.21.6.254` со стороны Arch Linux. Наличие ответов подтверждает установку физического и логического соединения.

# 3. Настройка резервного копирования конфигурации хоста Proxmox VE

Инструкция описывает процесс автоматизированного резервного копирования системной директории `/etc` (содержащей конфигурации кластера и виртуальных машин) на сервер Proxmox Backup Server (PBS).

## Этап 1. Создание учетной записи и API-токена (Сторона PBS)

1. В веб-интерфейсе PBS перейдите в раздел **Configuration** `[Конфигурация]` $\rightarrow$ **Access Control** `[Управление доступом]` $\rightarrow$ вкладка **User Management** `[Пользователи]`.
2. Нажмите **Add** `[Добавить]` и заполните данные:
   * **User name:** `backup_user`
   * **Realm:** `Proxmox Backup authentication server (pbs)`
   * Назначьте произвольный пароль и сохраните изменения.
3. Перейдите на вкладку **API Tokens** `[API токены]`.
4. Нажмите **Add** `[Добавить]`:
   * **User:** Выберите `backup_user@pbs`.
   * **Token Name:** Укажите идентификатор (например, `hostbackup`).
5. **ВАЖНО:** Скопируйте сгенерированный **Token Secret** `[Секрет токена]`. Он отображается только один раз. Полное имя токена примет вид: `backup_user@pbs!hostbackup`.

## Этап 2. Назначение прав доступа

Необходимо предоставить токену права на запись в требуемые пространства имен (Namespaces) вашего хранилища (Datastore).

1. Перейдите на вкладку **Permissions** `[Права доступа]`.
2. Нажмите **Add** $\rightarrow$ **API Token Permission**.
3. Заполните форму для первого узла:
   * **Path:** `/datastore/ваш_datastore/ваш_namespace_01`
   * **API Token:** `backup_user@pbs!hostbackup`
   * **Role:** `DatastoreBackup` (допускается `DatastoreAdmin` для автоматической ротации архивов).
4. Повторите процедуру для второго узла, изменив путь на `/datastore/ваш_datastore/ваш_namespace_02`.

## Этап 3. Настройка клиента резервного копирования (Сторона PVE)

Действия выполняются в консоли хоста Proxmox VE.

1. Установите клиент PBS (при его отсутствии):
   ```bash
   apt install proxmox-backup-client
   ```
2. Создайте исполняемый скрипт резервного копирования:
   ```bash
   nano /root/backup-host.sh
   ```
3. Внесите следующий код, заменив переменные на актуальные значения:
   ```bash
   #!/bin/bash

   # Переменные окружения для авторизации в PBS
   export PBS_REPOSITORY='backup_user@pbs!hostbackup@172.20.6.3:8007:ваш_datastore'
   export PBS_PASSWORD='ВАШ_СЕКРЕТ_ТОКЕНА'
   export PBS_FINGERPRINT='ОТПЕЧАТОК_СЕРТИФИКАТА_ПРИ_НЕОБХОДИМОСТИ'

   echo "Инициализация резервного копирования директории /etc..."
   # Запуск резервного копирования с указанием пространства имен
   proxmox-backup-client backup host-etc.pxar:/etc --ns ваш_namespace_01

   echo "Резервное копирование завершено."
   ```
4. Назначьте скрипту права на исполнение:
   ```bash
   chmod +x /root/backup-host.sh
   ```

**Проверка:** Запустите скрипт вручную (`/root/backup-host.sh`). В терминале должен отобразиться процесс вычисления контрольных сумм и статус `Upload summary`.

## Этап 4. Настройка расписания (Cron)

Для автоматического выполнения процесса скрипт добавляется в системный планировщик задач.

1. Откройте редактор расписания:
   ```bash
   crontab -e
   ```
2. Добавьте правило для ежедневного запуска в 03:00 ночи (вывод ошибок подавляется):
   ```bash
   0 3 * * * /root/backup-host.sh > /dev/null 2>&1
   ```

## Памятка: Процедура восстановления данных

Файловые архивы хоста не отображаются в стандартном интерфейсе хранилищ Proxmox VE. Для взаимодействия с ними предусмотрено два метода:

**Метод 1. Извлечение отдельных файлов (через веб-интерфейс PBS)**
1. Перейдите в раздел хранилища (Datastore) и выберите соответствующий Namespace.
2. Раскройте группу архивов `host/host-etc`.
3. Нажмите кнопку **File Restore** `[Восстановление файлов]` напротив требуемой даты.
4. Встроенный файловый менеджер позволит загрузить необходимый конфигурационный файл напрямую в браузер.

**Метод 2. Полное восстановление при аварии (Bare-metal recovery)**
1. В консоли чистой установки Proxmox VE экспортируйте переменные авторизации (`PBS_REPOSITORY` и `PBS_PASSWORD`).
2. Выполните команду загрузки всего архива во временную директорию:
   ```bash
   proxmox-backup-client restore host-etc.pxar /etc_backup --ns ваш_namespace_01
   ```
3. Перенесите необходимые файлы (ключи SSH, `storage.cfg`, конфигурации сетей) из `/etc_backup` в рабочий каталог `/etc` с последующей перезагрузкой системы.
