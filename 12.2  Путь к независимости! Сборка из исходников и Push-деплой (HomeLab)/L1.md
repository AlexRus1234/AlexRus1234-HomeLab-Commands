# Развертывание CI/CD конвейера для SFTPGo (GitOps)

---

*Архитектурная справка: Данный процесс переводит ручное управление сервисом SFTPGo на парадигму GitOps. Автоматизированный конвейер самостоятельно загрузит исходные коды, скомпилирует статический бинарный файл без избыточных зависимостей, поместит его во внутренний реестр пакетов и развернет на целевом LXC-узле.*

---

## Этап 1. Подготовка репозиториев и аутентификации

1. В веб-интерфейсе Forgejo создайте новую организацию с именем **Archive** (если она отсутствует).
2. Инициируйте создание зеркала исходного кода:
   * Перейдите в **Новая миграция** $\rightarrow$ **GitHub**.
   * Укажите URL: `https://github.com/drakkan/sftpgo.git`.
   * Активируйте опцию **Это зеркало**.
3. Создайте рабочую организацию для сборок с именем **Build**.
4. Сделайте форк зеркалированного репозитория:
   * Откройте репозиторий `sftpgo` в организации **Archive**.
   * Нажмите **Ответвление (Fork)**.
   * В качестве владельца выберите организацию **Build**, имя репозитория оставьте `sftpgo-build`.
5. Сгенерируйте маркер доступа для публикации пакетов в реестр:
   * Перейдите в **Меню профиля** $\rightarrow$ **Настройки** $\rightarrow$ **Приложения** $\rightarrow$ **Токены**.
   * Введите имя токена: `UPLOAD_TOKEN`.
   * Активируйте галочку прав доступа: `package: write`.
   * Нажмите **Генерировать** и скопируйте полученную строку.
6. Интегрируйте маркер в хранилище секретов репозитория:
   * Откройте репозиторий `sftpgo-build`.
   * Перейдите в **Настройки** $\rightarrow$ **Действия** $\rightarrow$ **Секреты**.
   * В поле имени укажите `UPLOAD_TOKEN`, в поле значения вставьте скопированный маркер. Нажмите **Добавить секрет**.

---

## Этап 2. Настройка конвейера сборки (Continuous Integration)

1. В репозитории `sftpgo-build` создайте директорию и манифест пайплайна по пути: `.forgejo/workflows/build.yml`.
2. Заполните файл конфигурацией сборки (замените `<IP_ВНУТРЕННЕГО_CA>`, `<ВАШ_ЛОГИН>` и `<ВАШ_ДОМЕН_FORGEJO>` на актуальные данные инфраструктуры):

```yaml
name: Build and Push SFTPGo

on:
  workflow_dispatch:
    inputs:
      target_tag:
        description: 'Какую версию собрать? (например: v2.7.1)'
        required: true
        default: 'main'
        type: string

jobs:
  build:
    runs-on: docker
    container:
      image: golang:alpine
    
    steps:
      - name: Install dependencies
        run: apk add --no-cache git curl bash

      - name: Checkout specific tag
        run: |
          curl -k https://<IP_ВНУТРЕННЕГО_CA>:9000/roots.pem -o /tmp/step-ca.crt
          git config --global http.sslCAInfo /tmp/step-ca.crt
          TAG_TO_BUILD="${{ github.event.inputs.target_tag || github.ref_name }}"
          git clone --branch $TAG_TO_BUILD --depth 1 ${GITHUB_SERVER_URL}/${GITHUB_REPOSITORY}.git .
          git config --global --unset http.sslCAInfo

      - name: Get Build Variables
        id: vars
        run: |
          echo "COMMIT=$(git describe --always --abbrev=8 --dirty || echo 'unknown')" >> $GITHUB_ENV
          echo "DATE=$(date -u +%FT%TZ)" >> $GITHUB_ENV
          TAG_TO_BUILD="${{ github.event.inputs.target_tag || github.ref_name }}"
          echo "PKG_VERSION=${TAG_TO_BUILD//\//-}" >> $GITHUB_ENV

      - name: Build SFTPGo Binary
        run: |
          CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -buildvcs=false -trimpath \
            -tags nopgxregisterdefaulttypes,disable_grpc_modules \
            -ldflags "-s -w -X github.com/drakkan/sftpgo/v2/internal/version.commit=${{ env.COMMIT }} -X github.com/drakkan/sftpgo/v2/internal/version.date=${{ env.DATE }}" \
            -o sftpgo

      - name: Upload Binary to Forgejo Registry
        run: |
          curl -fSR --cacert /tmp/step-ca.crt \
               --user "<ВАШ_ЛОГИН>:${{ secrets.UPLOAD_TOKEN }}" \
               --upload-file ./sftpgo \
               "https://<ВАШ_ДОМЕН_FORGEJO>/api/packages/Build/generic/sftpgo/${{ env.PKG_VERSION }}/sftpgo"
```
3. Сохраните манифест (создайте коммит).
4. Перейдите во вкладку **Действия (Actions)** репозитория.
5. Выберите пайплайн **Build and Push SFTPGo**, нажмите **Run workflow**, введите целевой тег (например, `v2.7.1`) и инициируйте запуск.
6. После успешного завершения пайплайна проверьте наличие скомпилированного файла: перейдите в профиль организации **Build** $\rightarrow$ вкладка **Пакеты**.

## Этап 3. Подготовка среды развертывания и генерация ключей

Для обеспечения беспарольного доступа runner-ов к целевому LXC-контейнеру необходимо настроить SSH-аутентификацию по ключу.

1. На локальной рабочей станции или управляющем сервере сгенерируйте криптографическую пару ключей стандарта `ed25519`:
   ```bash
   ssh-keygen -t ed25519 -f deploy_key
   ```
2. Выведите содержимое публичного ключа и скопируйте его:
   ```bash
   cat deploy_key.pub
   ```
3. Подключитесь к целевому LXC-контейнеру (серверу SFTPGo) и добавьте ключ в список доверенных:
   ```bash
   nano /root/.ssh/authorized_keys
   ```
   *Вставьте скопированный публичный ключ и сохраните файл.*
4. В веб-интерфейсе Forgejo создайте новый пустой репозиторий для инфраструктурного кода (например, `homelab-deploy`).
5. Перейдите в параметры репозитория `homelab-deploy`: **Настройки** $\rightarrow$ **Действия** $\rightarrow$ **Секреты**.
6. Создайте секрет с именем `SSH_PRIVATE_KEY` и вставьте в поле значения полное содержимое приватного ключа (содержимое локального файла `deploy_key`).

## Этап 4. Настройка конвейера развертывания (Continuous Deployment)

*Данный скрипт осуществляет подключение к целевому узлу по SSH, заменяет исполняемый файл на актуальную версию из реестра Forgejo и производит безопасный перезапуск системной службы.*

1. В репозитории `homelab-deploy` создайте файл манифеста развертывания: `.forgejo/workflows/deploy-sftpgo.yml`.
2. Заполните конфигурацию (укажите IP-адрес вашего LXC-контейнера и домен Forgejo):

```yaml
name: Deploy SFTPGo Update

on:
  workflow_dispatch:
    inputs:
      target_version:
        description: 'Какую версию развернуть? (например: v2.7.1)'
        required: true
        default: 'v2.7.1'
        type: string

jobs:
  deploy:
    runs-on: docker
    container:
      image: alpine:latest
      
    steps:
      - name: Setup SSH
        run: |
          apk add --no-cache openssh-client curl
          mkdir -p ~/.ssh
          echo "${{ secrets.SSH_PRIVATE_KEY }}" > ~/.ssh/id_ed25519
          chmod 600 ~/.ssh/id_ed25519
          echo -e "Host *\n\tStrictHostKeyChecking no\n\n" > ~/.ssh/config

      - name: Update SFTPGo in LXC
        env:
          TARGET_VERSION: ${{ github.event.inputs.target_version }}
          LXC_IP: "<IP_ВАШЕГО_LXC_КОНТЕЙНЕРА>" 
        run: |
          ssh root@$LXC_IP << EOF
          set -e
          echo "1. Останавливаем службу..."
          systemctl stop sftpgo
          
          echo "2. Скачиваем новый бинарник..."
          curl -k -fSR -o /usr/bin/sftpgo "https://<ВАШ_ДОМЕН_FORGEJO>/api/packages/Build/generic/sftpgo/${TARGET_VERSION}/sftpgo"
          chmod +x /usr/bin/sftpgo
          
          echo "3. Запускаем службу..."
          systemctl start sftpgo
          
          echo "4. Проверяем статус..."
          systemctl is-active --quiet sftpgo && echo "SFTPGo УСПЕШНО ЗАПУЩЕН!" || { echo "ОШИБКА ЗАПУСКА!"; exit 1; }
          
          echo "----------------------------------------"
          /usr/bin/sftpgo -v
          systemctl status sftpgo | grep "Active:"
          EOF
```
3. Сохраните манифест в ветке `main`.
4. Перейдите во вкладку **Действия (Actions)** репозитория `homelab-deploy`.
5. Выберите пайплайн **Deploy SFTPGo Update**, нажмите **Run workflow**, введите требуемую версию для установки (например, `v2.7.1`) и запустите.
6. Откройте логи процесса для верификации. Успешный деплой отобразит стадии скачивания файла, перезапуска демона Systemd, а также вывод новой версии и времени непрерывной работы службы (`Active: active (running)`).
