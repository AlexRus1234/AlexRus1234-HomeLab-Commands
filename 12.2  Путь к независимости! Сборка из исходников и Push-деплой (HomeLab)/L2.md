# Сборка кастомного Caddy с модулем Layer4 и настройка L4-маршрутизации

---

*Архитектурная справка: Для обеспечения доступа к внутренним сервисам (SFTP, SSH) из внешней сети по единому доменному имени требуется обработка «сырого» TCP-трафика на транспортном уровне модели OSI (Layer 4). Стандартный дистрибутив Caddy не включает данный функционал. Процесс ниже описывает автоматизированную сборку кастомного бинарного файла Caddy с внедрением плагина `caddy-l4` и его бесшовное развертывание.*

---

## Этап 1. Подготовка репозиториев (Зеркалирование исходного кода)

Для обеспечения суверенитета инфраструктуры необходимо создать локальные копии зависимостей перед началом сборки.

1. В веб-интерфейсе Forgejo перейдите в организацию **Archive** и создайте две новые миграции (выбрав **Новая миграция** $\rightarrow$ **GitHub**):
   * Репозиторий базового веб-сервера: `https://github.com/caddyserver/caddy.git`
   * Репозиторий L4-модуля: `https://github.com/mholt/caddy-l4.git`
   * *Для обеих миграций обязательно активируйте опцию **Это зеркало**.*
2. Перейдите в рабочую организацию **Build**.
3. Создайте новый пустой репозиторий с именем `caddy-build`.

---

## Этап 2. Настройка конвейера сборки (Continuous Integration)

В качестве сборочного окружения используется официальный контейнер `caddy:builder`, содержащий утилиту `xcaddy` для компиляции пользовательских модулей.

1. В репозитории `caddy-build` создайте директорию и файл манифеста: `.forgejo/workflows/build-caddy.yml`.
2. Внесите следующую конфигурацию (заменив переменные `<IP_ВНУТРЕННЕГО_CA>`, `<ВАШ_ЛОГИН>` и `<ВАШ_ДОМЕН_FORGEJO>`):

```yaml
name: Build Sovereign Caddy (with L4)

on:
  workflow_dispatch:
    inputs:
      caddy_version:
        description: 'Какую версию Caddy собрать? (например: 2.8.4)'
        required: true
        default: '2.8.4'
        type: string

jobs:
  build:
    runs-on: docker
    container:
      image: caddy:builder
    
    steps:
      - name: Install dependencies
        run: apk add --no-cache git curl bash

      - name: Configure Git Mirrors
        run: |
          echo "Загружаем корневой сертификат..."
          curl -k https://<IP_ВНУТРЕННЕГО_CA>:9000/roots.pem -o /tmp/step-ca.crt
          git config --global http.sslCAInfo /tmp/step-ca.crt
          
          echo "Настраиваем прозрачный перехват..."
          git config --global url."https://<ВАШ_ДОМЕН_FORGEJO>/Archive/caddy.git".insteadOf "https://github.com/caddyserver/caddy"

      - name: Build Custom Caddy
        env:
          CADDY_VERSION: ${{ github.event.inputs.caddy_version }}
          GOPRIVATE: "<ВАШ_ДОМЕН_FORGEJO>/*"
          GONOSUMDB: "<ВАШ_ДОМЕН_FORGEJO>/*"
        run: |
          echo "Собираем Caddy v$CADDY_VERSION с плагином L4..."
          xcaddy build v$CADDY_VERSION \
            --with github.com/mholt/caddy-l4=git.<ВАШ_ДОМЕН_FORGEJO>/Archive/caddy-l4.git@master
          ls -lh caddy

      - name: Upload Caddy to Registry
        env:
          CADDY_VERSION: ${{ github.event.inputs.caddy_version }}
        run: |
          curl -fSR --cacert /tmp/step-ca.crt \
               --user "<ВАШ_ЛОГИН>:${{ secrets.UPLOAD_TOKEN }}" \
               --upload-file ./caddy \
               "https://<ВАШ_ДОМЕН_FORGEJO>/api/packages/Build/generic/caddy/v${CADDY_VERSION}/caddy"
```
3. Перейдите во вкладку **Действия (Actions)**, выберите созданный пайплайн и нажмите **Run workflow** (используйте версию по умолчанию, например `2.8.4`).
4. По завершении убедитесь в наличии собранного пакета `caddy` во вкладке **Пакеты** организации **Build**.

## Этап 3. Настройка конвейера развертывания (Continuous Deployment)

Обновление маршрутизатора требует минимального времени простоя. Скрипт скачивает бинарный файл во временную директорию, осуществляет подмену системного файла и инициирует перезапуск демона.

1. Откройте репозиторий управления инфраструктурой (например, `homelab-deploy`, созданный ранее).
2. Создайте файл `.forgejo/workflows/deploy-caddy.yml` и заполните его:

```yaml
name: Deploy Caddy (Local)

on:
  workflow_dispatch:
    inputs:
      target_version:
        description: 'Версия для установки (например: v2.8.4)'
        required: true
        default: 'v2.8.4'
        type: string

jobs:
  deploy:
    runs-on: docker
    container: 
      image: alpine:latest
    steps:
      - name: Setup SSH
        run: |
          apk add --no-cache openssh-client curl bash
          mkdir -p ~/.ssh
          echo "${{ secrets.SSH_PRIVATE_KEY }}" > ~/.ssh/id_ed25519
          chmod 600 ~/.ssh/id_ed25519
          echo -e "Host *\n\tStrictHostKeyChecking no\n\n" > ~/.ssh/config

      - name: Deploy via SSH (Zero Downtime)
        env:
          VERSION: ${{ github.event.inputs.target_version }}
          CADDY_IP: "<IP_CADDY_СЕРВЕРА>" 
        run: |
          ssh root@$CADDY_IP << 'EOF'
          set -e
          echo "1. Скачиваем бинарник во временную папку..."
          curl -k -fSR -o /tmp/caddy_new "https://<ВАШ_ДОМЕН_FORGEJO>/api/packages/Build/generic/caddy/${VERSION}/caddy"
          
          echo "2. Заменяем бинарник на лету..."
          chmod +x /tmp/caddy_new
          mv /tmp/caddy_new /usr/bin/caddy
          
          echo "3. Бесшовный рестарт Caddy..."
          systemctl restart caddy
          
          echo "4. Проверка плагинов:"
          /usr/bin/caddy list-modules | grep -i "layer4" || { echo "Плагин L4 не найден!"; exit 1; }
          EOF
```
3. Запустите пайплайн через меню **Действия (Actions)**. В логах успешного выполнения должен отобразиться модуль `layer4`.

## Этап 4. Конфигурация транспортной маршрутизации (Layer 4)

После успешного обновления бинарного файла необходимо настроить правила переадресации TCP-портов в конфигурации прокси-сервера.

1. Подключитесь по SSH к серверу Caddy.
2. Откройте конфигурационный файл:
   ```bash
   nano /etc/caddy/Caddyfile
   ```
3. Добавьте блок `layer4` в начало файла (внутрь глобального блока или перед HTTP-маршрутами), указав IP-адреса целевых внутренних сервисов:

```caddy
{
    admin :2019 
    debug 

    # Блок настройки модуля layer4 для прямого TCP-трафика
    layer4 {
        # Маршрутизация SFTP-подключений (к SFTPGo)
        :65020 {
            route {
                proxy <IP_SFTPGO_СЕРВЕРА>:2022
            }
        }
        # Маршрутизация SSH-подключений (к Git/Forgejo)
        :65122 {
            route {
                proxy <IP_FORGEJO_СЕРВЕРА>:22
            }
        }
    }
}
```
4. Примените новую конфигурацию (без остановки службы):
   ```bash
   systemctl reload caddy
   ```

## Этап 5. Верификация подключения

Убедитесь в корректной работе L4-маршрутизации через внешний клиент (например, мобильное приложение или терминал рабочей станции).

1. Откройте клиент (например, FolderSync или консоль).
2. Инициируйте подключение со следующими параметрами:
   * **Сервер/Хост:** Доменное имя вашего сервера (модуль L4 не анализирует SNI/домены в данном контексте, маршрутизация происходит исключительно по порту).
   * **Порт:** `65020`
   * **Протокол:** SFTP
   * **Учетные данные:** Логин и пароль (или ключ) пользователя SFTPGo.
3. Соединение должно быть успешно установлено, открывая доступ к корневому каталогу файлового сервера.
